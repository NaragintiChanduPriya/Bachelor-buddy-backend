# Synthetic data

All data is generated by `scripts/generate_data.py`, not copied from the frontend fixtures (they
were used only as a reference for shape and style). Code: `scripts/seed/` (`vocab.py` curated
vocabularies, `reference.py` places, stores and fee rules, `catalog.py` and `users.py` builders,
`load.py` loader, `checks.py` consistency checks).

## Regenerating

```bash
uv run python scripts/setup_db.py --seed            # create everything and seed the app database
uv run python scripts/generate_data.py              # seed the app database (skipped if unchanged)
uv run python scripts/generate_data.py --force      # reload even if unchanged
uv run python scripts/generate_data.py --demo --users 50   # also seed the demo user and 50 synthetic users
uv run python scripts/generate_data.py --test       # the test database (the tests also do this)
```

A run records a fingerprint (generator version, seed, user count, anchor) in `seed_runs`. An
identical later run is skipped, so `--seed` is cheap to repeat.

**Only seeded rows are replaced.**
- **Catalog tables** are upserted by primary key, and rows the new dataset no longer has are
  deleted.
- **Seeded users** (`users.is_seeded`) are deleted with everything they own, then inserted
  again.
- **Accounts you registered yourself are kept.** Their alerts and lists still point at the same
  products and items, because ids are deterministic.
- **Scheduler state:** `job_runs` is cleared, so jobs run again on the new data.

Everything happens in one transaction, so a failure leaves the database as it was.

## Determinism

- One seed (`SEED_VALUE`, default 42). Every entity gets its own stream,
  `random.Random(f"{seed}:{kind}:{id}")`, so adding rows never shifts existing ones, and string
  seeding doesn't depend on `PYTHONHASHSEED`.
- Faker (`en_IN`) is used only for synthetic people's names, seeded per user. Emails are
  `@example.com`.
- **The anchor** is the clock's "now" (`CLOCK_MODE=real`: today). Every date (price history,
  offers, availability, and seeded people's expenses) is relative to it. The test database is
  anchored at 15 Nov 2026 12:30 IST (`scripts/seed/anchors.py`).
- **People:** by default the app database gets the catalog only and **no users**: real people
  sign up. `--demo` adds the demo user Arjun and `--users N` adds synthetic users; reseeding
  replaces only seeded users (`users.is_seeded`), never real accounts. The test database always
  has Arjun plus three synthetic users.
- `tests/seed/test_generator.py` builds everything twice and asserts byte-identical output.

## Generation rules

**Places.** 15 areas: HSR Layout, Koramangala, BTM Layout, Bellandur, Marathahalli, Whitefield,
Electronic City, Indiranagar, Jayanagar, Kadubeesanahalli, Sarjapur Road, Domlur, JP Nagar,
Mahadevapura and Bommanahalli. Market PG rent is set per area (Indiranagar and Koramangala
highest, Electronic City lowest); co-living is 1.4× and shared flats 1.3×.

**Food.**
- **Names and places:** prefix + local-flavoured core + type suffix ("Sri Ganesh Tiffin Room"),
  unique across the city. Each place is located within 1.4 km of its area's centre.
- **Menus:** sampled from curated templates. Darshinis ₹15-90, messes ₹40-180, tiffin plans,
  restaurants ₹80-340, cafés. Each menu has at least two popular mains, and veg places list only
  veg dishes.
- **Prices:** `avgMealPrice` is the average popular main. For tiffin services it is the
  26-meal monthly plan ÷ 26.
- **Hours and delivery:** realistic opening hours (some dinner-only, some past midnight); about
  5% sponsored.
- **Delivery quotes:** marked-up item price plus each platform's fees. The per-km fee is added
  per request, from the user's office.

**Groceries.**
- **Catalog:** 160 generic items, 16 in each of the contract's 10 categories. Prices start
  from a neighbourhood-kirana base and vary by store type and item kind.
- **Store patterns:**
  - Quick commerce: +8-22% (fresh produce +15-35%).
  - Supermarkets: competitive on packaged goods.
  - Kiranas: best on fresh produce.
  - Online bulk: cheapest on staples and household items, with bulk packs at 7-15% off.

**Products.**
- **Catalog:** 27 per category: shirts, jeans, formal shoes, backpacks, earphones, watches,
  raincoats and helmets. Brands are invented.
- **Prices:** MRP sits in a category range; the normal price is 55-85% of MRP, ending in 9.
- **History:** 180 days per platform with weekly noise, a slow trend, and a festival sale about
  6 weeks back. One pattern per product:
  - `steady`
  - `inSale` (on sale today)
  - `afterSale` (sales every 4-6 weeks, the last one ended 4-14 days ago)
  - `festivalSpike` (prices up to +14% in the last 3 weeks)
  - `recentDrop` (dropped 20% 4-10 days ago)

  Other platforms follow at half the sale depth.
- **Stock:** about 8% are out of stock on one platform.

**Offers.**
- **Live offer 001:** the contract's worked example, always live: HDFC credit 10% up to ₹500
  over ₹1,500 on ShopNest, ending in 2 days.
- **The rest:** card offers (HDFC, SBI, ICICI, Axis, Kotak; credit, debit or any), coupons and
  cashback across shopping, food-delivery and grocery platforms.
- **Eligibility:** some need cards the demo user doesn't hold (Kotak, HDFC debit), so
  eligibility genuinely varies.

**Homes.** About 8 per area, PG 50%, co-living 25%, shared flat 25%. Rent is the area and type
average × 0.76-1.24, rounded to ₹500 and clamped to ±25%. Deposits, sharing, food (80% of PGs),
amenities, notice periods and availability are realistic. Commutes are road distance
(straight-line distance × 1.35 plus jitter) with bike and bus minutes.

**Users and expenses.**
- **Profiles:**
  - Salary ₹22,000-95,000 and a 5-25% savings goal.
  - A home area, and an office near a tech park.
  - Food preference: veg 45%, non-veg 40%, eggetarian 10%, vegan 5%.
  - 1-3 saved cards.
- **Spending:** each user has a spending profile (frugal, normal or overspender) that sets
  spend as a share of each category limit.
- **Expenses:**
  - Rent lands on the 1st-3rd.
  - Bills are recurring or subscriptions.
  - Weekday meals are at eateries near the office, weekend meals near home.
  - About 18% of food is delivery orders at night.
  - Groceries, travel, shopping and misc are drawn from templates.

  Category totals hit their targets exactly. The current month runs only up to today, and
  nothing is in the future.

**The demo user, Arjun** (arjun@demo.com):
- **Profile:** 24, software engineer, ₹40,000 salary, ₹8,000 goal. Home is HSR Layout, the
  office is in Bellandur (Orbit Tech Campus). Veg, with four cards.
- **This month on the 15th:** rent ₹14,000, food ₹5,250 (70% of ₹7,500, including 11
  deliveries), groceries ₹1,680, shopping ₹700 (₹1,800 left), travel ₹1,130, bills ₹1,340,
  misc ₹920. Total ₹25,020, exactly the contract's example.
- **The six finished months saved:** ₹2,100, 3,400, 4,600, 5,800, 6,900 and 7,600 (snapshots
  match his expenses).
- **Also:** 13 notifications (4 unread), 4 price alerts (one triggered), 8 recommendations (7
  followed), and the 22-item monthly grocery list.

**Guarantees for the demo questions:** at least 3 cheap veg places open at lunch near Bellandur,
formal shoes under ₹1,500 deliverable within days, and PGs under ₹10,000 in Marathahalli.

## Consistency checks (after every load)

The load fails if any of these is violated:
- Every listing has 6-23 menu items, and its price range matches its dishes.
- Every rent is within 25% of its area average.
- Every home has a commute to every tech park.
- Price history has 180 consecutive days ending today for every product and platform, and
  today's price equals the last history point.
- Every grocery item is priced at all 8 stores.
- Budget limits add up to the salary, and every seeded user has 7 budgets.
- Snapshots equal salary minus that month's spending.
- No expense is in the future.
- On the 15th, Arjun's food spend is exactly ₹5,250.

## Names

Every business, platform, store, brand and PG is invented: FeastDrop, ZipCart, ShopNest,
Stridewell, "Sri Ganesh Tiffin Room" and so on. Real bank names are used only for card offers,
which is factual. `tests/seed/test_generator.py` checks every generated name against a list of
real brands. People's names are synthetic (Faker) with `@example.com` emails.
